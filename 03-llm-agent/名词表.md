# D3 名词表 —— 每个词都讲透

> 用法：看代码或任务卡时遇到不认识的词，回来查这里。
> 每个名词按「一句话说清 → 类比 → 今天在哪用到 → 深入一点」四段写。

---

## LLM（Large Language Model，大语言模型）

- **一句话**：读过海量文本、靠"猜下一个字"来生成内容的 AI 模型。
- **类比**：一个读过全互联网的"接龙大师"——你说"床前明月光"，它接"疑是地上霜"。
- **今天在哪用到**：`rag_demo.py` 第 3 步把 prompt 递过去等回答的那个"它"，就是 LLM。
- **深入一点**：它逐字预测下一个最可能出现的字，接几千次就是一篇文章。所以它"说得像那么回事"和"说得对"是两回事——它并不真的理解世界，只是语言学得像。这也是它为什么会"一本正经胡说八道"（幻觉）。

## prompt（提示词）

- **一句话**：你递给模型的完整输入文本。
- **类比**：给新员工的 task 工单：交代身份、给材料、说清楚要什么。
- **今天在哪用到**：`build_prompt()` 拼出来的那一大段，就是 prompt。
- **深入一点**：模型没有记忆，每次对话从零开始，你给多少信息它就基于多少发挥。写 prompt 的技巧本质是"把话说清楚"：角色、任务、格式、例子，给得越明确输出越稳定。

## RAG（Retrieval-Augmented Generation，检索增强生成）

- **一句话**：提问时先从资料里检索相关段落，连同问题一起递给模型，让它"照资料回答"。
- **类比**：开卷考试——不带课本是闭卷（裸问模型），递小纸条是 RAG。
- **今天在哪用到**：整个 `rag_demo.py` 就是 RAG 的三步：切分 → 检索 → 生成。
- **深入一点**：为什么需要它？模型有两个短板：知识有截止日期、没见过你的私有文档。与其花大价钱重训模型，不如提问时把资料递过去。附带好处：每句回答有出处，可核对。企业里"文档问答"产品底层几乎都是 RAG。

## chunking（切分 / 分块）

- **一句话**：把长文档切成小段，方便按段检索。
- **类比**：把课本裁成一张张卡片，考试只带相关的几张。
- **今天在哪用到**：`load_chunks()` 按 `##` 标题切 `material.md`。
- **深入一点**：切分策略是门学问：按标题切保主题完整，按字数切保长度均匀；段太大稀释相关性，段太小丢上下文。段间还可以"重叠"一点，防止关键句被切断。

## retrieve（检索）

- **一句话**：计算问题和每个段落的相关性，挑出最相关的几段。
- **类比**：查字典时先猜"这个词大概在 D 开头那几页"。
- **今天在哪用到**：`retrieve()` 函数，RAG 三步的第 2 步。
- **深入一点**：检索器是 RAG 的质量瓶颈——它没捞到的段，模型永远看不到。真实系统里这一步从"几万段里毫秒捞出最相关的"，靠的是向量检索。

## bigram（二元组）

- **一句话**：把文字按每两个字一组切开。"大语言模型" → 大语/语言/言模/模型。
- **类比**：看两个人像不像，不比单根骨头，比"关节怎么长的"。
- **今天在哪用到**：`bigrams()` 函数，中文检索零依赖方案。
- **深入一点**：中文没有空格分词（英文单词天然分开），专业做法用 jieba 等分词库但要安装。bigram 绕过分词：两字组天然携带局部词序，抗噪也够用。缺点是没有语义理解——"体测"和"体育考试"在它眼里毫不相干。

## 余弦相似度（cosine similarity）

- **一句话**：比较两个数字向量"方向"有多接近，0~1 之间，越大越像。
- **类比**：两个人从同一起点出发，走的方向越一致， Cosine 越接近 1。
- **今天在哪用到**：`cosine()` 函数，算"问题和段落像不像"的尺子。
- **深入一点**：公式 = (A·B) / (|A|×|B|)。除以模长是为了防止长文档占便宜。它只看方向不看长度——所以"一段话提到很多两字组"不会直接赢，赢的是"方向对得上"。

## 词频向量 / Counter

- **一句话**：把一段文字变成"每种两字组出现几次"的账本。
- **类比**：超市小票——买了什么、各几件。
- **今天在哪用到**：`Counter(text[i:i+2] ...)` 一行生成。
- **深入一点**：文字必须变成数字，计算机才能算。词频向量是最朴素的"文字变数字"方法；更高级的做法是 embedding。

## embedding（嵌入 / 向量化）

- **一句话**：用神经网络把文字变成一串数字（向量），语义越近向量越近。
- **类比**：给每段文字发一个"意思坐标"，聊相似话题的坐标就挨得近。
- **今天在哪用到**：今天没用到——但真实 RAG 的检索器就是它。bigram 是它的"穷亲戚"。
- **深入一点**：bigram 只认字面重合，embedding 懂语义："怎么退款"能检索到"退货流程"，哪怕两句话字面毫不相同。代价是要下载模型、要算力。

## 向量数据库

- **一句话**：专门存向量、支持"找出最相近的 N 个"的数据库。
- **类比**：按"意思"索引发货的仓库，不是按货架号。
- **今天在哪用到**：没用到，`chunks` 列表就是它的极简版（7 个段落，顺序扫一遍就完了）。
- **深入一点**：百万级段落时顺序扫描太慢，向量数据库用近似最近邻（ANN）算法毫秒级检索。常见的有 FAISS、Milvus、pgvector。

## top_k

- **一句话**：每次检索最多挑前几名。`TOP_K = 4` 就是最多挑 4 段。
- **类比**：考试小纸条只准抄 4 段——抄几段是权衡。
- **今天在哪用到**：配置区的 `TOP_K`，命令行 `--top-k`。
- **深入一点**：注意是"最多"：`retrieve()` 最后的 `if score > 0` 会把 0 分的段落过滤掉，所以 `TOP_K=4` 有时只拼出 2 段。段数多材料全但掺噪音（相似度 0.023 的段落就是凑数混进来的），段数少精准但可能漏。真实项目里靠试。

## Agent（智能体）

- **一句话**：不止回答问题，还能自己规划步骤、调用工具（搜索/计算/写文件）把任务做完的 AI。
- **类比**：聊天机器人是"你问一句它答一句"的客服；Agent 是"你说目标，它自己拆解步骤去干"的助理。
- **今天在哪用到**：`material.md` 里有一节专门讲它；你现在用的对话助手就是 Agent。
- **深入一点**：从聊天框到 Agent 的关键差别：从"被动应答"变成"主动规划 + 工具调用"。LangChain、Dify 是常见框架。

## API / API key

- **一句话**：API 是程序之间互相调用的"服务窗口"；API key 是调用时要出示的"门票"。
- **类比**：API 是餐厅前台，API key 是你的会员卡号——报号码才给你上菜。
- **今天在哪用到**：`ask_llm()` 调 DeepSeek；`API_KEY` 配置项。
- **深入一点**：key 按调用量计费，所以绝不能写进公开代码（会被盗刷）。标准做法是放环境变量——这也是 `os.environ.get("LLM_API_KEY")` 那行的用意。

## SDK（Software Development Kit，软件开发工具包）

- **一句话**：官方封装好的工具包，让调用复杂服务像用本地函数一样简单。
- **类比**：遥控器 vs 电路板——SDK 是遥控器，不用你懂红外协议。
- **今天在哪用到**：`openai` 这个包就是 OpenAI 官方 SDK。
- **深入一点**：没有 SDK，你得自己拼 HTTP 请求、处理 JSON、管重试；有了 SDK，三行代码搞定。

## OpenAI 兼容 API / base_url

- **一句话**：一套"长得像 OpenAI"的接口标准；base_url 是"前台在哪"的地址。
- **类比**：USB 接口标准——任何厂商照着做，插上线就能用。
- **今天在哪用到**：DeepSeek/Kimi/通义都兼容 OpenAI 格式，所以同一个 `openai` 包能打所有家，改 `BASE_URL` 就切换。
- **深入一点**：这是 2023 年后形成的行业默契：OpenAI 定义了事实标准，别家照做省开发者的事。base_url 换成 `http://localhost:11434/v1` 就连本地 ollama。

## CLI（Command-Line Interface，命令行界面）

- **一句话**：在终端里敲命令操作程序的方式（相对于点点点的图形界面）。
- **类比**：对服务员报菜名（CLI）vs 指着图片点菜（GUI）。
- **今天在哪用到**：`python rag_demo.py 文档.md --top-k 3` 就是 CLI 用法；这个 demo 本身就是个 CLI 程序。
- **深入一点**：CLI 的优势是可脚本化、可远程、资源占用小——服务器上基本没有图形界面，CLI 是工程师的基本生存技能。

## 终端 / shell / PowerShell / Bash

- **一句话**：终端是敲命令的窗口；shell 是解释命令的程序。PowerShell 是 Windows 的 shell，Bash 是 Linux/Mac 的。
- **类比**：同一个"打字指挥电脑"的动作，两边方言不同。
- **今天在哪用到**：你被 PowerShell 5.1 不认 `&&` 和 `printf` 卡了一次——那就是方言不通。
- **深入一点**：`&&`（A 成功再跑 B）是 Bash 写法，PowerShell 5.1 用 `;`。这就是"同一份教程换个系统就跑不通"的根源，也是为什么程序员都讨厌环境问题。

## 标准库 / 第三方库 / pip / venv

- **一句话**：标准库 = Python 自带预装；第三方库 = 别人写的要下载；pip = 下载工具；venv = 每个项目独立的"包隔离间"。
- **类比**：标准库是手机预装 App，第三方库是应用商店，venv 是"工作号"——每个项目一个，互不污染。
- **今天在哪用到**：本程序**零第三方依赖**（只用标准库），所以不用建 venv 直接跑。
- **深入一点**：`pip install openai` 才会需要 venv。为什么隔离？A 项目要 numpy 1.0、B 项目要 numpy 2.0，不隔离就打架。

## import / 模块

- **一句话**：import = 把别人写好的工具箱搬进来；模块 = 一个 .py 文件就是一个工具箱。
- **类比**：`import re` 就像做菜时把"调味架"拿到手边。
- **今天在哪用到**：文件开头那 6 行 import。
- **深入一点**：标准库模块不用装；第三方模块要先 pip install。`from math import sqrt` 是"只从 math 里拿 sqrt 这一件工具"，比 `import math` 更省字数。

## 变量 / 函数 / 参数 / 返回值

- **一句话**：变量 = 贴了标签的数据盒子；函数 = 打包好的一段可复用逻辑；参数 = 递给函数的原材料；返回值 = 函数交回来的成品。
- **类比**：函数是榨汁机：水果是参数，果汁是返回值，榨汁机本身不关心你姓什么。
- **今天在哪用到**：`TOP_K` 是变量，`retrieve(question, chunks, top_k)` 是函数带三个参数，`return chunks` 是返回值。
- **深入一点**：函数的最大价值是"一次定义多处调用 + 屏蔽内部复杂度"——`main()` 里只写 `load_chunks(path)`，不用管里面几行代码。

## 字符串 / 列表 / 字典 / 集合 / 元组

- **一句话**：字符串 = 文字；列表 = 有序的一队数据；字典 = 键值对查询表；集合 = 去重后的一堆；元组 = 不可改的列表。
- **类比**：列表是购物小票（有顺序），字典是字典（查词），集合是一袋不重复的彩票。
- **今天在哪用到**：`chunks` 是列表，`{"title": ..., "text": ...}` 是字典，`set(a) & set(b)` 是集合，`(score, chunks[i])` 是元组。
- **深入一点**：选型口诀：要顺序用列表、要查询用字典、要去重用集合、要防改用元组。

## 切片 [i:i+2]

- **一句话**：从数据里"切一段"出来，`text[i:i+2]` = 从第 i 位开始切 2 个。
- **类比**：从队伍里喊"第 3 到第 5 号出列"。
- **今天在哪用到**：`bigrams()` 里 `text[i:i+2]`，滑动窗口切两字组的核心一行。
- **深入一点**：切片是 Python 的招牌语法，`[:40]` 取前 40 个，`[::-1]` 直接反转。左闭右开（取不到 i+2）是初学者的经典困惑点。

## for 循环 / while 循环 / 列表推导式

- **一句话**：for = 对一堆东西逐个处理；while = 条件满足就一直转；列表推导式 = 一行写完 for 的压缩写法。
- **类比**：for 是"逐个点名"，while 是"不到下课不下课"，推导式是点名册的速记法。
- **今天在哪用到**：`for part in parts` 遍历段落；`while True` 主循环等提问；`[(score, i) for ...]` 是推导式。
- **深入一点**：`while True` 靠内部的 `break` 退出——没有 break 就是死循环。推导式可读性换简洁，别嵌套超过两层。

## if / try-except（异常处理）

- **一句话**：if = 条件分流；try-except = 把可能出错的代码包起来，出错时执行预案而不是崩溃。
- **类比**：try-except 就像安全气囊——正常时感觉不到，撞车时救命。
- **今天在哪用到**：`if not m: continue` 跳过无标题段；`ask_llm()` 里 except 兜住网络错误。
- **深入一点**：程序崩溃和"优雅地报告错误"是新手和高手的分水岭。用户输入错误文件、网络断线，都该由 except 接住，给出人话提示。

## 正则表达式（regex / re 模块）

- **一句话**：用一串"模式字符"描述要匹配的文本形态，是字符串的"找茬神器"。
- **类比**：Ctrl+F 的超级版——不只找固定文字，还能找"所有以数字开头的行"。
- **今天在哪用到**：`r"\n(?=## )"` 按标题切文档；`r"##\s*(.+)"` 提取标题。
- **深入一点**：`r"..."` 是 Python 的"原始字符串"标记（反斜杠不转义，正则必备）。`\s`=空白、`\d`=数字、`(?=...)`=环视（只看不吃）。正则的坑：写复杂了没人看得懂，包括三天后的你自己。

## markdown

- **一句话**：用 `#`、`*` 等符号标记格式的纯文本写法，.md 文件。
- **类比**：带批注的 plain text——任何编辑器能开，渲染后是排版好的文档。
- **今天在哪用到**：`material.md` 语料、所有任务卡和复盘卡片都是 markdown。
- **深入一点**：`#` 一级标题、`##` 二级标题。本程序按 `##` 切段，就是利用 markdown 的结构性——这也是为什么 demo 语料选 markdown 而不是 txt。

## 文件路径 / __file__ / UTF-8

- **一句话**：路径 = 文件在地盘上的地址；`__file__` = 当前脚本自己的路径；UTF-8 = 中文不乱的编码。
- **类比**：路径是门牌号，UTF-8 是"都说普通话"的约定。
- **今天在哪用到**：`MATERIAL` 用 `__file__` 定位同目录语料；`open(..., encoding="utf-8")` 防中文乱码。
- **深入一点**：Windows 默认编码 GBK，Linux 默认 UTF-8——同一份代码跨系统乱码，99% 是忘了写 `encoding="utf-8"`。

## git commit / push / GitHub 仓库 / clone

- **一句话**：commit = 给当前文件拍快照存档；push = 快照上传远程；仓库 = 项目的完整历史档案馆；clone = 把远程仓库完整下载到本地。
- **类比**：commit 是游戏存档，push 是存档上传云，clone 是换台电脑接着玩。
- **今天在哪用到**：今天 3 个 commit：骨架 `352c7e6`、升级 `e41c969`（主仓库），发布 `757cb2b`（mini-rag）。
- **深入一点**：commit 只存"差异"，所以仓库体积小、历史清晰。commit message 写清楚"改了什么、为什么"，三个月后的你会感谢自己。

## localhost / 端口 / HTTP

- **一句话**：localhost = "我本机"；端口 = 本机上不同服务的门牌号；HTTP = 网络请求的通用语言。
- **类比**：一栋楼（本机）里很多公司（服务），端口号是房间号。
- **今天在哪用到**：`BASE_URL` 默认 `https://api.deepseek.com`；ollama 是 `http://localhost:11434/v1`。
- **深入一点**：`127.0.0.1` = localhost 的数字写法；5000/8000/11434 都是常见服务端口。你 D2 跑笑话 API 时的 `localhost:5000` 就是本机端口。

## ollama / DeepSeek

- **一句话**：ollama = 在你自己电脑上跑大模型的工具；DeepSeek = 国产大模型 + 便宜兼容的 API 服务。
- **类比**：ollama 是"在家做饭"，DeepSeek API 是"点外卖"——前者免费隐私好但慢，后者快而全但要花钱。
- **今天在哪用到**：`BASE_URL`/`MODEL` 两个配置项在它俩之间切换。
- **深入一点**：ollama 一条命令下载运行开源模型（Qwen/Llama），OpenAI SDK 改 base_url 就能对接。个人体验用云 API 更省事，本地部署的隐私/离线价值主要在企业场景。

## argparse

- **一句话**：Python 标准库，专门解析命令行参数（你敲的 `文档.md`、`--top-k 3`）。
- **类比**：餐厅门口的迎宾——把你的话听明白，领到对应座位。
- **今天在哪用到**：`main()` 开头的 `parser`，自动生成 `--help` 帮助文本。
- **深入一点**：`nargs="?"` 表示可选参数；`type=int` 自动转型；`--top-k` 这种双横线是"长选项"惯例。

## 降级设计（fallback）

- **一句话**：外部条件不满足时，自动切换到次要方案，保证核心体验不中断。
- **类比**：外卖软件叫不到车，自动提示"改骑共享单车"——事还是办成了。
- **今天在哪用到**：没配 API key 时，程序不报错，转为打印 prompt 让你手动贴网页版。
- **深入一点**：这是"低成本试错"的工程思想：核心功能不依赖外部服务，外部服务只是加速器。写程序时多问一句"如果这步失败了，最差的体验是什么"。

## 零依赖

- **一句话**：程序只用语言自带的工具，不装任何第三方包。
- **类比**：不用买任何食材，用厨房现成的调料做出一顿饭。
- **今天在哪用到**：整个 `rag_demo.py` 只用标准库，所以 clone 下来 `python rag_demo.py` 直接跑。
- **深入一点**：零依赖 = 传播成本最低（不怕版本冲突、不怕装不上）、教学透明度最高（每个函数都能看懂）。代价是重复造轮子——真实项目该用库就用库。
