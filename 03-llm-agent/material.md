# 大语言模型与 RAG 通俗读本

> 这是 D3 体验日的问答语料。`rag_demo.py` 会按 `##` 标题把它切成小段，你问什么，它就检索哪几段。
> 读完它，今天的核心概念你就有了一半。

## 大语言模型在做什么

大语言模型的全部工作，可以用一个字概括：猜。你输入一段文字，它逐个预测下一个最可能出现的字，把预测出的字接在末尾，再预测下一个。这个"接龙"过程重复几千次，就得到一段通顺的回答。它并不真的"理解"世界，它擅长的是把在海量文本里学到的语言规律用出来。所以它能写诗、能写代码、能聊天，但也可能一本正经地胡说八道——因为"说得像那么回事"和"说得对"是两件事。

## 为什么需要提示词

提示词（prompt）就是你给模型的输入。模型没有记忆，每次对话都是从零开始，你把多少信息放进 prompt，它就只能基于这些信息发挥。写 prompt 的技巧，本质上是"把话说清楚"的技巧：角色、任务、格式、例子，给得越明确，输出越稳定。同一个模型，prompt 不同，表现可能天差地别——这也是为什么有人把调 prompt 叫做"和模型沟通的艺术"。

## 大模型的两个短板

第一个短板是知识过期：模型的训练数据有截止日期，之后发生的事它不知道。第二个短板是不了解你的私有信息：你公司的文档、你的笔记、你这周的工作记录，它都没见过。更麻烦的是，你没法为了问几个问题就重新训练一个模型——那太贵了。于是人们想：能不能不改模型本身，在提问的时候，把相关资料一起递给它？

## RAG 给模型一本资料书

RAG（检索增强生成）就是这个思路，做法分三步。第一步切分：把长文档切成合适的小段，就像把一本书裁成一张张卡片。第二步检索：用户提问时，先算出问题和哪几段最相关，只把这几段挑出来。第三步生成：把挑出的段落和问题一起拼进 prompt，让模型"根据资料"回答。这样一来，模型不需要重新训练，也能回答文档里的内容；而且每句回答都有出处，可以核对。RAG 是当下企业里用大模型最主流的姿势，你用的很多"文档问答"产品，底层都是它。

## Agent 让模型学会用工具

如果只会回答问题，模型只是个聊天框。Agent 的思路是再进一步：给模型一套工具——搜索引擎、计算器、数据库查询、发邮件——再给它一个规划能力，让它自己决定"这个问题该先查什么、再算什么、最后怎么汇总"，然后一步步调用工具把任务做完。你此刻正在用的对话助手，就是一个 Agent：它会自己决定要不要搜索、读文件、写代码。从聊天框到 Agent，关键差别就一个：从"你问一句它答一句"，变成"你给个目标，它自己拆解步骤"。

## 为什么这个方向火也变得快

大模型应用层是近两年需求最猛的软件开发方向之一：写 API 对接、设计 prompt、搭 RAG、做工具调用和工作流。但它的迭代速度也是所有方向里最快的——模型能力每几个月上一个台阶，去年要写几十行代码搞的技巧，今年新模型可能一句话就能做。所以这个方向的核心竞争力，不是背诵某个框架，而是"把 AI 能力和真实业务流程焊死"的工程能力：懂业务、会拆解、能评估效果、能控制成本。变化快意味着要持续学，也意味着新人永远有机会。
