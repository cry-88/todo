# D2 名词表 —— 后端名词逐个讲透

> 看代码遇到不认识的词，回来查这里。每个名词按「一句话 → 类比 → 今天在哪用到 → 深入一点」四段写。
> 配套源码：`app.py`（服务器）、`client.html`（前端页面）、`test_app.py`（测试）。

---

## 后端 / 服务器

- **一句话**：后端是“用户看不见的那半边程序”，跑在服务器上，负责数据、规则和计算。
- **类比**：餐厅后厨——顾客（前端）点菜，后厨（后端）做菜、管仓库、定规矩。顾客只面对菜单和传菜口。
- **今天在哪用到**：`app.py` 整个文件就是你的后厨；你终端里跑起来的那个进程就是你的服务器。
- **深入一点**：后端三大件日常：接口设计（对外提供什么服务）、数据存取（存哪、怎么查）、业务规则（校验、权限、流程）。今天三条全碰了。

## HTTP（超文本传输协议）

- **一句话**：浏览器和服务器之间“一问一答”的通信规则。
- **类比**：打电话的礼仪：先自报家门（请求头），说事（请求体），等对方回应（响应），挂电话（连接关闭）。
- **今天在哪用到**：每次浏览器访问 `/api/joke/random`，就是一次完整的 HTTP 问答。
- **深入一点**：HTTP 是无状态的——服务器不记得你是谁，每次请求都从头开始。“记住登录状态”要靠 cookie/token（那是后面的事）。

## 请求 / 响应（request / response）

- **一句话**：浏览器发给服务器的叫请求，服务器答回来的叫响应。
- **类比**：点菜（请求）和上菜（响应）。后端的全部工作就是“收到请求 → 处理 → 给响应”。
- **今天在哪用到**：`random_joke()` 函数的入参世界是 request，return 的就是 response。
- **深入一点**：请求里有什么：方法（GET/POST）、网址、请求头（Content-Type 等）、请求体（POST 的数据）。响应有什么：状态码、响应头、响应体（JSON）。

## URL / 路由 / 路由表 / 装饰器

- **一句话**：URL 是网址；路由是“什么网址交给哪个函数”的映射；路由表是全部映射；装饰器 `@app.route()` 是往表里登记的动作。
- **类比**：114 查号台：你报名字（URL），它转接分机（函数）。`@app.route` 就是“把名字和分机号写进通讯录”。
- **今天在哪用到**：`@app.route("/api/joke/<int:joke_id>")` ——尖括号部分是“网址里的变量”，会作为参数传给函数。
- **深入一点**：`<int:joke_id>` 的类型转换（int）自动挡掉非数字请求，比进来再判断省事。路由顺序也有讲究：先注册的具体规则优先（`/api/joke/random` 写在 `/api/joke/<int:joke_id>` 前面对付“random 不是数字”的歧义）。

## HTTP 方法：GET / POST

- **一句话**：GET 是“要数据”（参数在网址里）；POST 是“送数据”（数据在请求体里）。
- **类比**：GET 是隔着窗户喊“来份菜单”；POST 是填表投递——表格内容在信封里，不在喊的话里。
- **今天在哪用到**：`client.get("/api/joke/random")`（要）；`methods=["POST"]` 的投稿接口（送）。
- **深入一点**：还有 PUT（改）、DELETE（删）——合起来 CRUD（增删改查），是后端接口的四原色。选方法的规矩：GET 只读不改数据（否则刷新浏览器就出事），写操作用 POST/PUT/DELETE。

## 状态码（status code）

- **一句话**：响应的三位数字暗语，告诉浏览器“这事成没成、为什么”。
- **类比**：客服的标准话术编号：200“成了”、404“没这东西”、400“你说法有问题”。
- **今天在哪用到**：200（成功）、201（创建成功，比 200 更精确）、400（投稿内容为空）、404（查无此笑话）。
- **深入一点**：分类记：2xx 成功、3xx 重定向、4xx 你（客户端）的错、5xx 我（服务器）的错。排错时先看状态码，能省一半时间。

## JSON

- **一句话**：跨语言数据交换格式，长得像 Python 字典。
- **类比**：数据界的普通话。
- **今天在哪用到**：`jsonify(joke)` 把字典变成 JSON 响应；前端 `res.json()` 再解析回 JS 对象。
- **深入一点**：`ensure_ascii=False` 这行让中文直接显示，不然全变 `\u4f60\u597d` 天书。真实项目里 JSON 的结构（怎么嵌套、字段怎么命名）要和前端商量着定——这就是“接口设计”。

## API / 接口

- **一句话**：程序对外提供的“服务窗口”，规定了怎么调用、返回什么。
- **类比**：餐厅的菜单+点餐规则：菜名（端点）、做法（参数）、上什么（返回结构）。
- **今天在哪用到**：`/api/joke/random` 等五个端点，就是本 demo 的全部 API。
- **深入一点**：好的 API 三要素：路径语义化（`/api/joke/3` 而不是 `/api/getJoke?id=3`）、状态码诚实、返回结构稳定（前端依赖你的字段名，乱改=断人财路）。

## Flask / 框架

- **一句话**：Flask 是 Python 的轻量 Web 框架——帮你处理 HTTP 脏活，你只写业务逻辑。
- **类比**：预制厨具：火候控制、排烟都封装好了，你只管炒菜。
- **今天在哪用到**：`from flask import ...`、`app = Flask(__name__)`、`@app.route`、`app.run()`。
- **深入一点**：框架 vs 裸写：没有框架你得自己解析 HTTP 报文（原始字节流）——能学底层，但干活要用框架。同类还有 Django（大而全）、FastAPI（新、快、自动生成文档）。

## 前后端分离

- **一句话**：前端（浏览器页面）和后端（API 服务器）是独立的两块，靠 HTTP 对话。
- **类比**：前台服务员和后厨：职责分开，靠“点菜单”（API）沟通。
- **今天在哪用到**：`/play` 把 client.html 发给浏览器，页面里的 fetch 再调 API——页面归页面，数据归数据。
- **深入一点**：分离的好处：两边能各自换技术栈（前端 React、后端 Go），能分别部署，页面能直接复用别人的 API。今天这个 demo 是“同源”最小版；跨域的坑（CORS）等遇到再说。

## 内存 vs 文件持久化

- **一句话**：变量活在内存里（断电/重启就没），文件写在磁盘上（重启还在）。
- **类比**：内存是草稿纸，文件是档案柜。笑话 API 第一版只有草稿纸，投稿重启就丢；后来加了档案柜（jokes.json）。
- **今天在哪用到**：`jokes = load_jokes()`（启动读档）、`save_jokes()`（投稿后归档）。
- **深入一点**：文件方案的极限：数据一多（十万条）查找变慢、多人同时投稿会冲突（覆盖）。这两个问题正是 D5 数据库（SQLite/MySQL）要解决的。

## pytest / assert / 测试客户端

- **一句话**：pytest 是测试框架；assert 是断言（不成立就报错）；test_client 是“假浏览器”，不真开服务器就能测接口。
- **类比**：流水线质检员：每台产品（代码改动）过一遍固定检查项（测试），不合格就拦下。
- **今天在哪用到**：`test_app.py` 五个测试；`client.get(...)` / `client.post(...)` 就是假浏览器在跑流程。
- **深入一点**：测试的价值在“回归”：今天改 A 改坏了 B，测试立刻报警。专业团队的标准：改代码前先跑测试，提交前必须全绿。测试“关系”（`== len(jokes)`）而不是“快照”（`== 14`），数据变了测试也不失效。

## debug 模式

- **一句话**：开发期专用开关：改代码自动重启、出错显示详细原因。
- **类比**：厨房的监控直播——开发时看得越细越好，营业时可不能给顾客看。
- **今天在哪用到**：`app.run(debug=True, port=5050)`——保存文件服务器自动重启，浏览器刷新就是新代码。
- **深入一点**：上线必须关 debug：错误详情会暴露代码路径和结构，是给攻击者递刀。端口 5050 也是开发惯例（避开被占的 5000）。

## 端口（port）

- **一句话**：一台机器上不同服务的“门牌号”，0-65535。
- **类比**：一栋写字楼（机器）里很多公司（服务），端口号是房间号。
- **今天在哪用到**：`http://localhost:5050`——localhost 是本机，5050 是笑话服务器的房间。
- **深入一点**：常见默认：80（HTTP）、443（HTTPS）、3306（MySQL）、5000/8000（开发常用）。端口被占 = 房间被抢，报 `Address already in use`，换一间（port=5051）或查出占用者。

## 请求体 / 请求头 / Content-Type

- **一句话**：请求体是“信封里装的东西”（POST 的数据）；请求头是“信封上的说明”；Content-Type 声明“我送的是什么格式”。
- **类比**：寄快递：物品是请求体，运单是请求头，“易碎品/文件”标注是 Content-Type。
- **今天在哪用到**：投稿时 `headers: {"Content-Type": "application/json"}`——不写这行，服务器按表单解析你的 JSON，直接 400。
- **深入一点**：这是“格式协商”的最小案例。真实项目还有 `Accept: application/json`（我能收什么）、认证头（`Authorization: Bearer token`）。

## fetch / async / await（前端侧）

- **一句话**：fetch 是浏览器发网络请求的函数；async/await 是“等网络结果”的写法。
- **类比**：fetch 是下单，await 是“外卖到了叫我”，async 标记这个函数里可能有等待。
- **今天在哪用到**：client.html 的 getJoke() 和 addJoke()——前端和后端对话的全部魔法就这一个函数。
- **深入一点**：不用 await 的老写法是回调函数和 Promise 链（`.then().then()`），可读性差。async/await 把异步写得像同步，是现代 JS 的标配。

## “永远不信任客户端输入”

- **一句话**：前端送来的一切（空的、超长的、伪造的）都可能被动手脚，后端必须自己再校验一遍。
- **类比**：前台递来的表格可能是客人瞎填的，后厨得自己核对——前台检查是为了体验，后厨检查是为了不出事。
- **今天在哪用到**：`if not setup or not punchline: return 400`——空投稿在这里被挡住。
- **深入一点**：安全铁律：校验在后端做，不能只靠前端（前端 JS 用户可以随便改）。同族法则还有“密码不明文存”（D2 番外讲过哈希）、“SQL 注入防参数化查询”（D5 见）。

## 装饰器（decorator）

- **一句话**：`@名字` 写在函数头上，给函数“贴标签”或“包一层”，不改函数本身。
- **类比**：给员工发工牌：不改变他本人，但系统（Flask）凭工牌认人。
- **今天在哪用到**：`@app.route("/")` 就是“工牌上写着：这个函数负责 / 这个网址”。
- **深入一点**：装饰器是 Python 的大杀器：日志、权限校验、缓存都能用装饰器优雅地“贴”到函数上，业务代码干干净净。

## `if __name__ == "__main__"`

- **一句话**：“直接运行本文件时才执行下面；被别的文件 import 时不执行”。
- **类比**：电影的“正片”和“预告片”：单独放这片是正片，拼盘放映时它不自动播。
- **今天在哪用到**：app.py 最后——pytest import app 时不会真启动服务器。
- **深入一点**：`__name__` 是 Python 给模块贴的名字：直接运行 = `"__main__"`，被 import = 模块名（"app"）。几乎所有 Python 脚本都该有这行。
